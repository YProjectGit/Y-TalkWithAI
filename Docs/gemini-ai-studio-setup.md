# Google AI Studio セットアップ手順

音声インタラクション・ワークショップ用 / Gemini Developer API を Unity から使うための準備

---

## このチュートリアルでやること

Unity から Gemini を呼び出すために必要な **APIキーを1本取得**し、**それが正しく動くことを確認**するところまでを行います。所要時間は10〜15分です。

やることは4ステップだけです。

1. Google AI Studio にログインする
2. APIキーを1本つくる
3. キーを安全に保管する
4. キーが動くか、その場で確認する

> **重要な前提**
> ここで触るのは **Google AI Studio** だけです。ネットで検索すると「Google Cloud Console」「Vertex AI」「サービスアカウント」「gcloud」といった情報が大量に出てきますが、**このワークショップでは一切使いません**。それらの手順に迷い込まないよう注意してください。

---

## ステップ0:必要なもの

- Google アカウント（普段使っているもので構いません）
- ブラウザ（Chrome 推奨）
- クレジットカードは **不要** です

---

## ステップ1:Google AI Studio にログインする

1. ブラウザで `https://aistudio.google.com` を開きます。
2. 自分の Google アカウントでログインします。
3. 初回は利用規約（Terms of Service）が表示されます。内容を確認して同意します。

同意すると、あなた専用の作業環境が自動で用意されます。この時点で、裏側に「デフォルトのプロジェクト」が1つ自動作成されています（この存在を意識する必要はありません）。

---

## ステップ2:APIキーをつくる

1. 画面左のメニュー、または右上あたりにある **「API Keys」** （APIキー）を開きます。
2. **「Create API key」**（APIキーを作成）ボタンを押します。
3. 数秒で、`AIza...` で始まる長い文字列のキーが発行されます。
4. **「Copy」** を押してキーをコピーします。

> **2026年時点の注意（必ず読んでください）**
> - **必ずこの場で新しくキーを作ってください。** 今 AI Studio で新規作成されるキーは、自動的に正しい種類（auth キー）になります。
> - 逆に、**以前どこかで作った古いキーを使い回すのは避けてください。** 古い種類のキー（Standard キー）は、近い将来サービス側で受け付けられなくなる予定です。「新しく作れば正しい」と覚えておけば大丈夫です。
> - しばらく使われずに放置されたキーは無効化されることがあります。ワークショップの直前に作るのが確実です。

---

## ステップ3:キーを安全に保管する

APIキーは **あなたのアカウントに紐づいた鍵** です。他人に知られると、あなたのアカウントで勝手に使われ、最悪の場合あなたに料金が請求されます。以下を必ず守ってください。

**やってはいけないこと**

- キーをソースコード（`.cs` ファイルなど）に直接書き込む
- キーを SNS・チャット・スクリーンショットに写り込ませる
- キーを GitHub など公開される場所にアップロードする

**やること**

- キーは、コードとは別のテキストファイル（例：`apikey.txt`）に貼り付けて保管する
- そのファイルを Git で管理する場合は、`.gitignore` に必ず追加して**リポジトリに含めない**
- キーは後からいつでも AI Studio で作り直せます。もし漏らしてしまったら、古いキーを削除して新しいキーを作り直してください

> なぜここまで言うか：2026年、公開されてしまった Google のキーが第三者に悪用され、数十万円規模の請求が発生した事例が実際に複数あります。「たかがキー」ではなく「自分の財布に直結する鍵」だと考えてください。

---

## ステップ4:キーが動くか確認する（超重要）

Unity に進む前に、**キーが本当に生きているか**をこの場で確かめます。ここを飛ばすと、後で Unity がうまく動かないとき「キーの問題なのかコードの問題なのか」が切り分けられず、時間を大量に溶かします。

### 方法A：ターミナル（コマンドライン）で確認する

Mac の「ターミナル」、Windows の「コマンドプロンプト」や「PowerShell」を開き、以下を実行します。
`ここにキーを貼る` の部分を、自分のキーに置き換えてください。

```bash
curl "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent" \
  -H "x-goog-api-key: ここにキーを貼る" \
  -H "Content-Type: application/json" \
  -X POST \
  -d '{"contents":[{"parts":[{"text":"こんにちは。ひとことで自己紹介して。"}]}]}'
```

日本語の応答テキストを含む JSON が返ってくれば **成功** です。キーは正常に使えます。

### 方法B：AI Studio の画面上で確認する

コマンドラインが不安な場合は、AI Studio のチャット画面（左メニューの「Chat」など）で、モデルに何か話しかけてみてください。返事が返ってくれば、あなたのアカウントで Gemini が使える状態だと確認できます。
（※厳密にはキー経由の疎通確認とは別ですが、アカウントが有効かの確認にはなります。確実なのは方法Aです。）

---

## 返ってくるデータの構造（予習）

方法Aで返ってくる JSON の中で、**欲しい応答テキスト**は次の場所に入っています。

```
candidates → [0] → content → parts → [0] → text
```

Unity 側では、この階層をたどってテキストを取り出します。今は「応答は candidates の中に入っている」とだけ覚えておけば十分です。

---

## Unity から呼ぶときの3点セット（次回の予習）

Unity（`UnityWebRequest`）から呼ぶときも、やることは方法Aの curl と同じです。必要なのは次の3つだけです。

| 要素 | 中身 |
|---|---|
| **URL** | `https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent` |
| **ヘッダー** | `x-goog-api-key: <あなたのキー>` と `Content-Type: application/json` |
| **ボディ（JSON）** | `{"contents":[{"parts":[{"text": ここに送る文章 }]}]}` |

URL の中の `gemini-2.5-flash` を別のモデル名に変えれば、使うモデルを切り替えられます。

---

## つまずいたときのチェックリスト

| 症状 | 確認すること |
|---|---|
| `401` / `403` エラー | キーの貼り間違い（前後に余計な空白・改行が入っていないか）。キーの種類が古くないか（新しく作り直す） |
| `429` エラー | 短時間に叩きすぎ。無料枠のレート上限に達している。少し待つ |
| `404` エラー | URL のスペルミス。`v1`ではなく`v1beta`になっているか。モデル名が正しいか |
| 応答が空 | 送った JSON の形が正しいか（`contents` → `parts` → `text` の入れ子） |
| 日本語が文字化け | ファイルやリクエストの文字コードが UTF-8 になっているか |

---

## 用語ミニ辞典

- **Google AI Studio**：ブラウザで Gemini を試したり、APIキーを発行したりできる入り口。今回使うのはここだけ。
- **API キー**：あなたのアカウントで Gemini を呼ぶための鍵。1本あれば足りる。
- **Gemini Developer API**：AI Studio のキーで叩ける、開発者向けの Gemini API。今回使うのはこれ。
- **モデル名（例：gemini-2.5-flash）**：どの頭脳を使うかの指定。速くて日本語も得意な Flash を基本に使う。
- **無料枠（Free Tier）**：クレカなしで一定回数まで無料で使える枠。学習・制作には十分。ただし送った内容がモデル改善に使われる可能性があるため、**個人情報や見せたくない内容は送らない**こと。

---

## この先の流れ

1. （今ここ）APIキーを取得し、疎通確認できた
2. 次回：Unity で「文字を送って Gemini の返事を受け取る」最小プログラムを動かす
3. その後：マイク録音 → 音声を Gemini に渡して応答 → 音声合成（TTS）で読み上げ、と積み上げる

キーの疎通確認（ステップ4）まで終わっていれば、次回すぐに Unity の実装に入れます。

# 5.ScreenToSpeech 実装プラン

## 要点（サマリー）

- **何をするか**: マウスで描ける **ドローイングパッド** を Live API に渡し、描き進めるあいだに **声で解釈** する。カメラは使わない。
- **パイプライン**: キャンバス（Texture2D）→ **Live API（JPEG フレーム in → ネイティブ音声 out）** → 再生。4 と同じ通信。REST の Vision→TTS は使わない。
- **UX**: シャッター／Stream トグルは置かない。線が入ったら、dirty なキャンバスを約1秒間隔で送る（前ターン完了待ち）。**消す** で白紙に戻す。
- **UI**: 4 の送信／受信2分割・段階バー・Setup JSON・System Instruction 欄は **出さない**。大きな紙・消す・短い状態・解釈の字幕だけ。
- **コピー派生**: 共通基底は作らない。`VisionToSpeech.cs` の接続／送受信／再生をコピーし、入力を描画パッドに差し替える。
- **触らないもの**: 1A〜4 の挙動。6 以降は作らない。
- **完了条件**: シーン・スクリプト・README・本プランの UI イメージ。クラウドのため Editor 検証は省略。
- **一言**: 4 が「外の世界を見る Live」なら、5 は「いま描いている紙を見る Live」。裏側は隠して体験を先に出す。
- **適用状況**: 実装済み（シーン・スクリプト・README・UIイメージ）。

| | 4.VisionToSpeech | 5.ScreenToSpeech（本プラン） |
|---|------------------|------------------------------|
| 通信 | WebSocket Live ×1 | **同じ** |
| 入力 | WebCam JPEG | **描画パッドの JPEG** |
| 操作 | Space シャッター／Stream トグル | **描くだけ（自動送信）＋消す** |
| 出力 | 声 ＋ transcription（吹き出し） | **声 ＋ 短い字幕**（ログ欄なし） |
| 可視化 | 送信／受信2分割 | **出さない**（体験画面だけ） |

## 学習上の位置づけ

```text
[4]  Camera ═════════► Live API ══════► Audio     … 外の世界（WebCam）
[5]  Screen ═════════► Live API ══════► Audio     … いま描いている紙
```

- 4 で「JPEG フレームを `realtimeInput` で送る」を見たあと、5 は **入力源だけ画面（自分で描いた絵）** に替える。
- シリーズ既定の「パイプラインを隠さない」の例外。このデモは **描く→声が返る** を先に体験する。
- 学生が追う山場は、カメラの `GetPixels` ではなく **キャンバス Texture2D を JPEG にして同じ Live メッセージで送る** こと。

---

## 処理の骨格

```text
Play
  → APIキー読込
  → 白いキャンバスを用意（ローカル描画）
  → Live セッション接続（setup: AUDIO + voice + transcription + media_resolution）

マウスで描く
  → キャンバスが dirty
  → 約1秒間隔 かつ 前ターンが終わっていれば
      activityStart → JPEG → 短い実況指示 → activityEnd
  → サーバから PCM ＋ output transcription
  → 再生／字幕を更新（新しい送信時は前の再生を止める）

[消す]
  → 紙を白紙に戻す。空のキャンバスは送らない
```

公式の入出力前提は 4 と同じ。

| | 形式 |
|---|------|
| 送信映像 | JPEG フレーム、目安 **最大約1 FPS**、推奨 **768×768** 前後 |
| 受信音声 | raw 16-bit PCM, **24 kHz**, little-endian |
| プロトコル | ステートフル **WebSocket（WSS）** |
| モデル例 | `gemini-3.1-flash-live-preview`（4 と同じ・インスペクタで変更可） |

## UX 詳細（判断の固定）

| 操作 | 動作 |
|------|------|
| マウスドラッグ | キャンバスに線を描く |
| 自動送信 | インクがあり dirty なら、約1秒間隔で1ターン送る。Space も Stream トグルも置かない |
| 空の紙 | 送らない |
| 消す | 白紙に戻す。字幕も消す。次に描くまで送信しない |
| マイク | **使わない** |

「書きながら」の送り方は、**dirty ＋間隔** を採用する（線の途中でも、いまのピクセルを送る）。ペンを上げるまで待たない。前ターンが終わるまでは次を送らない。

新しいターンを送るときは、前の解説音声のキューを捨てて止める（古い実況が重ならないようにする）。

## UI 構成

4 の3ペインは使わない。画面のほとんどを紙にする。

```text
┌──────────────────────────────────────────────────────────┐
│  5.ScreenToSpeech          描いてください     [消す]     │
│                                                          │
│           ┌──────────────────────────────┐               │
│           │                              │               │
│           │     白いドローイングパッド     │               │
│           │     （マウスで描く）          │               │
│           │                              │               │
│           └──────────────────────────────┘               │
│                                                          │
│     「三角の屋根と四角い窓。家に見えます。」               │
└──────────────────────────────────────────────────────────┘
```

画面に出すもの:

1. **キャンバス** … 体験の本体。オフホワイトの紙、暗いインク
2. **消す** … 紙を白紙に戻す唯一の操作ボタン
3. **状態** … 短い1行（接続中／描いてください／見てます／話しています／エラー）
4. **字幕** … いまの声の内容（output transcription）。プロトコルログではない

画面に出さないもの:

- 段階バー、Setup JSON、送信／受信ログ、System Instruction 欄、吹き出し履歴

System Instruction と `voiceName` は **インスペクタだけ**。デモ用の既定文をスクリプトに持ち、共有の `Common/SystemInstruction.txt` は使わない（テキストチャット向けの文のため）。

Prefab / Resource は、実ファイルが必要になるまで作らない。吹き出し Prefab は使わない。

### `ScreenToSpeech.cs` の流れ（読む順）

1. `Start` — キー、体験 UI、`AudioSource`、**Live 接続**、解釈ループ開始
2. 解釈ループ — dirty かつインクありなら約1 FPS で1ターン送信
3. フレーム送信 — キャンバス → JPEG → Base64 → `realtimeInput`（4 と同じメッセージ形）
4. 受信ループ — audio → 再生キュー / transcript → 字幕（4 踏襲、ログ欄なし）
5. `OnDestroy` — セッション切断

### 4 から流用／捨てるもの

| 流用 | 捨てる／置き換える |
|------|-------------------|
| WebSocket 接続、Setup、受信 PCM 再生、transcription 抽出 | WebCam、Space シャッター、Stream トグル、送信／受信ペイン、段階バー、吹き出し |

## リスク・注意

| 点 | 扱い |
|----|------|
| 空送信 | インクが無い紙は送らない |
| 1 FPS 制限 | 間隔を約1秒。`isTurnBusy` で重ね送りしない |
| 実況の重複 | 新ターン開始時に再生キューを捨てる |

| メインスレッド | 4 と同様、受信→UI/Audio の戻しをコメントで明示 |
| セキュリティ | 教材は APIキー直結。README で ephemeral token に一言 |

## 判断の固定

- **Live API 一セッション**（REST Vision→TTS はしない）
- 応答は **AUDIO** ＋ output transcription（字幕用）
- 入力は **ドローイングパッド**（OS のデスクトップキャプチャにはしない）
- UX は **描く＋消すだけ**。Space / Stream トグルは置かない
- 送信は **JPEG・長辺768前後・約1 FPS・dirty のときだけ**
- **裏側のテキスト欄は出さない**（4 の例外）
- Firebase 等のラッパー SDK は使わない
- 共通基底クラスは作らない

実装済み。クラウド環境のため Editor 検証は対象外。
